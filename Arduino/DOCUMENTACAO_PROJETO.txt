================================================================================
          DOCUMENTAÇÃO DO PROJETO: MONITORAMENTO IOT COM BLE E MQTT
================================================================================
Dispositivos: Cinto (ESP32-C3) -> Âncoras (ESP32) -> Broker Mosquitto -> interface.py
Filtro / Código Identificador: "OQPNB"

--------------------------------------------------------------------------------
PARTE 1: ARQUITETURA, FUNCIONAMENTO DOS CÓDIGOS E FLUXO DE DADOS
--------------------------------------------------------------------------------

1. VISÃO GERAL DO SISTEMA
-------------------------
O objetivo do sistema é monitorar dados vitais e de movimento de um usuário
utilizando um cinto inteligente (Cinto), transmitir as leituras sem fios por
Bluetooth Low Energy (BLE Advertising), capturar esses pacotes por meio de âncoras
distribuídas pelo ambiente (Anchors) filtrando apenas dispositivos autorizados ("OQPNB"),
e repassar as medições via Wi-Fi/MQTT para um computador executando um broker
Mosquitto e uma interface de análise em Python.

Fluxo dos dados:
  [Sensores ECG + MPU6050]
             │
             ▼
     [cinto_v3 (ESP32-C3)] ──(BLE Adv + Scan Response)──► [anchor_v3 (ESP32)]
                                                                 │
                                                          (Wi-Fi / MQTT)
                                                                 ▼
                                                        [Mosquitto Broker]
                                                                 │
                                                                 ▼
                                                        [interface.py]


2. CINTO V3 (cinto_v3.ino) - COLETA E EMISSÃO DE DADOS
------------------------------------------------------
O cinto opera em um microcontrolador ESP32-C3 com duas tarefas principais não-bloqueantes:

A) Coleta de ECG e Cálculo Real de BPM (250 Hz / a cada 4000 µs):
   - Pino analógico A0 (sinalCardio) com AD8232; pinos digitais 4 (lop) e 3 (lom)
     para verificação de eletrodos soltos (Leads-off).
   - Filtro Passa-Alta (~0.6 Hz): Remove a flutuação de linha de base e respiração.
   - Filtro Passa-Baixa (~40 Hz): Suaviza ruídos elétricos de alta frequência.
   - Detecção de Picos R com Limiar Adaptativo:
     * O envelope acompanha o sinal com decaimento exponencial.
     * Um batimento é registrado quando o sinal supera o limiar (60% do envelope).
     * Período refratário de 250 ms (impede contagem dupla da mesma onda).
     * Janela RR aceita entre 300 ms (200 BPM) e 2000 ms (30 BPM).
     * O BPM final é calculado pela mediana dos últimos 5 intervalos RR:
       BPM = 60000 / mediana(RR)
     * Timeout de 3 segundos sem batimento ou eletrodos desconectados zera o BPM
       e ativa a flag de aviso (leads_off).

B) Coleta do MPU6050 (Acelerômetro + Giroscópio) e Envio BLE (a cada 250 ms):
   - Leitura direta via barramento I2C (Wire) com timeout de 100 ms para não travar
     caso os cabos se soltem.
   - Aceleração em X, Y, Z convertida para 'g' (divisor 16384.0).
   - Velocidade angular (Giroscópio) em X, Y, Z convertida para '°/s' (divisor 131.0).

C) Formatação e Transmissão BLE (NimBLE):
   - O cinto NÃO requer conexão pareada (connectionless); ele grita os dados via
     Advertising (difusão contínua a cada 100 ms, atualizando os valores a cada 250 ms).
   - Para garantir que nenhuma leitura seja cortada pelo limite de 31 bytes do BLE:
     * Pacote Principal (Manufacturer Data com Company ID 0xFFFF):
       Contém exatamente 24 bytes binários estruturados:
         - magic: "OQPNB" (5 bytes) -> permite filtragem imediata.
         - versao: 2 (1 byte).
         - beltNum: 1 (1 byte).
         - seq: contador sequencial de 0 a 255 (1 byte).
         - ax, ay, az: inteiros de 16 bits (mili-g).
         - gx, gy, gz: inteiros de 16 bits (0.1 graus/s).
         - bpm: 8 bits (0 a 255 BPM real).
         - flags: 8 bits (bit0: eletrodo solto, bit1: erro MPU, bit2: bpm válido).
         - ecg: 16 bits (amostra bruta filtrada do ECG).
     * Pacote Secundário (Scan Response):
       Envia o nome completo do dispositivo ("CINTO_OQPNB01") quando solicitado
       pelo scanner ativo da âncora.


3. ÂNCORA V3 (anchor_v3.ino) - ESCUTA, FILTRAGEM E ENCAMINHAMENTO
----------------------------------------------------------------
A âncora opera em um ESP32 padrão equipado com Wi-Fi e BLE simultâneos:

A) Escuta e Filtragem BLE:
   - Escuta passiva e ativamente o rádio BLE na sala com parâmetros otimizados
     (Intervalo 100 ms, Janela 80 ms, deixando tempo livre para o rádio Wi-Fi).
   - Modo de recepção contínua (start duration = 0).
   - O callback de recepção avalia cada pacote recebido na sala:
     * Verifica se a string "OQPNB" está presente no nome OU dentro do Manufacturer Data.
     * Dispositivos de terceiros (fones, relógios, celulares) são descartados sem processamento.
   - Quando encontra o pacote v2 binário do cinto:
     * Desempacota os 24 bytes para grandezas físicas reais (g, graus/s, BPM, flags).
     * Obtém o RSSI (intensidade do sinal em dBm, que indica a proximidade).

B) Desacoplamento por Fila FreeRTOS:
   - Como o callback do NimBLE roda em uma tarefa de rádio sensível a interrupções,
     a âncora NÃO publica no MQTT dentro do callback.
   - A leitura é enfileirada em uma fila FreeRTOS (`xQueueSend`).
   - O `loop()` principal retira os dados da fila e faz a publicação MQTT via `PubSubClient`.

C) Conexão Wi-Fi e Publicação MQTT:
   - Reconexão automática e não-bloqueante tanto para o Wi-Fi quanto para o MQTT.
   - Configura Last Will and Testament (LWT): publica "offline" no tópico de status
     caso a âncora perca energia ou caia da rede.
   - Publica um JSON estruturado para o tópico `oqpnb/anchor/<ANCHOR_ID>`:
     {
       "anchor": 1,
       "belt": "CINTO_OQPNB01",
       "belt_num": 1,
       "mac": "...",
       "rssi": -62,
       "seq": 15,
       "ax": 0.012, "ay": -0.040, "az": 0.985,
       "gx": -1.2, "gy": 0.4, "gz": 0.1,
       "bpm": 74,
       "bpm_valid": true,
       "ecg": 2048,
       "leads_off": false,
       "mpu_error": false,
       "ms": 142500
     }


4. INTERFACE PYTHON (interface.py) - VISUALIZAÇÃO E ARMAZENAMENTO
-----------------------------------------------------------------
Script para computador que atua como cliente MQTT:
- Conecta ao Mosquitto e assina o tópico curinga `oqpnb/anchor/#`.
- Exibe em tempo real no console cada leitura recebida com decodificação de sensores.
- Exibe tabela periódica (a cada 5 segundos) com:
  * RSSI atual e RSSI médio por par Cinto x Âncora.
  * Estimativa de localização por proximidade ("O cinto X está mais perto da âncora Y").
  * BPM atual e alertas de eletrodos soltos ou falhas de sensor.
- Gravação opcional em arquivo CSV (`--csv leituras.csv`) para histórico e gráficos.


================================================================================
PARTE 2: GUIA PRÁTICO - INSTALAÇÃO DO MOSQUITTO E CONFIGURAÇÃO
================================================================================

1. INSTALAÇÃO DO ECLIPSE MOSQUITTO NO WINDOWS
---------------------------------------------
1.1. Baixe o instalador oficial para Windows x64:
     Site: https://mosquitto.org/download/
     (Exemplo: mosquitto-x.x.x-install-windows-x64.exe)

1.2. Execute o instalador mantendo o caminho padrão:
     `C:\Program Files\mosquitto`

1.3. O instalador configura o Mosquitto como um Serviço do Windows com inicialização automática.


2. CONFIGURAÇÃO DO MOSQUITTO (mosquitto.conf)
---------------------------------------------
Por padrão nas versões recentes (v2.0+), o Mosquitto só aceita conexões vindas do próprio
computador (localhost / 127.0.0.1) e rejeita dispositivos externos como os ESP32.
É OBRIGATÓRIO ajustar o arquivo de configuração:

2.1. Abra o Bloco de Notas ou VS Code como ADMINISTRADOR.
2.2. Abra o arquivo:
     `C:\Program Files\mosquitto\mosquitto.conf`
2.3. No final do arquivo, adicione as seguintes duas linhas:

     listener 1883 0.0.0.0
     allow_anonymous true

     * `listener 1883 0.0.0.0`: instrui o broker a escutar na porta 1883 em TODAS as
       interfaces de rede (Ethernet, Wi-Fi, etc.).
     * `allow_anonymous true`: permite conexão das âncoras sem exigir usuário/senha.

2.4. Salve o arquivo.

2.5. Reinicie o serviço do Mosquitto para aplicar as mudanças:
     Abra o PowerShell como Administrador e execute:
     ```powershell
     Restart-Service mosquitto
     ```


3. CONFIGURAÇÃO DO FIREWALL DO WINDOWS 11
-----------------------------------------
Para que os ESP32 consigam alcançar a porta 1883 do seu computador pela rede local:

3.1. Liberar a porta via PowerShell (Modo Administrador):
     ```powershell
     New-NetFirewallRule -DisplayName "Mosquitto MQTT 1883" -Direction Inbound -Protocol TCP -LocalPort 1883 -Action Allow -Profile Private,Domain
     ```

3.2. Verificar Perfil de Rede (Obrigatório):
     Se a sua rede Wi-Fi estiver marcada como "Pública", o Windows bloqueará a conexão.
     - Vá em: Iniciar > Configurações > Rede e Internet > Wi-Fi.
     - Clique na sua rede conectada.
     - Certifique-se de que o "Tipo de perfil de rede" esteja marcado como "Privada".


4. DESCOBRIR O IP DO COMPUTADOR BROKER
--------------------------------------
No computador onde o Mosquitto está instalado, abra o PowerShell ou Prompt de Comando e rode:
```powershell
ipconfig
```
Localize o adaptador "Adaptador de Rede Sem Fio Wi-Fi" e anote o campo:
`Endereço IPv4 . . . . . . . . . . . : 192.168.X.XXX`
Este é o endereço que será colocado no código das âncoras.


5. CONFIGURAÇÃO DAS ÂNCORAS (anchor_v3.ino)
-------------------------------------------
Abra o arquivo `anchor_v3/anchor_v3.ino` no Arduino IDE antes de gravar em cada placa:

No início do arquivo, ajuste os parâmetros:
```cpp
// ============================================================
// CONFIGURAÇÕES (EDITAR AQUI)
// ============================================================
#define ANCHOR_ID 1                    // Número desta âncora (use 1 para a primeira, 2 para a segunda, etc.)

#define WIFI_SSID     "NOME_DO_SEU_WIFI"
#define WIFI_PASSWORD "SENHA_DO_SEU_WIFI"

#define MQTT_BROKER   "192.168.X.XXX"  // IP do computador encontrado no ipconfig
#define MQTT_PORT     1883
#define MQTT_USER     ""               // Deixe vazio caso allow_anonymous esteja ativo
#define MQTT_PASS     ""
```

IMPORTANTE: Se você tiver mais de uma âncora, mude apenas o `#define ANCHOR_ID`
para 2, 3, etc., ao gravar nas outras placas. Isso garante que cada âncora publique
em seu próprio tópico (`oqpnb/anchor/1`, `oqpnb/anchor/2`, etc.).


6. PREPARAÇÃO DO AMBIENTE PYTHON E EXECUÇÃO DA INTERFACE
--------------------------------------------------------
6.1. Caso ainda não tenha o Python instalado:
     - Baixe o instalador no site oficial (https://www.python.org/).
     - No instalador, marque a caixa "Add python.exe to PATH".

6.2. Instale a biblioteca do cliente MQTT:
     Abra o terminal (PowerShell ou Prompt de Comando) e instale o pacote `paho-mqtt`:
     ```powershell
     pip install paho-mqtt
     ```

6.3. Como rodar a interface:
     Navegue até a pasta do projeto e execute:

     A) Monitoramento padrão (se estiver rodando no mesmo PC do Mosquitto):
        ```powershell
        python interface.py
        ```

     B) Monitoramento apontando para outro IP na rede e gravando em CSV:
        ```powershell
        python interface.py --broker 192.168.X.XXX --csv leituras.csv
        ```

     C) Parâmetros úteis disponíveis:
        --broker <IP>     : IP do broker Mosquitto (padrão: localhost)
        --port <PORTA>    : Porta MQTT (padrão: 1883)
        --csv <ARQUIVO>   : Salva todas as leituras em formato CSV
        --summary <SEG>   : Intervalo em segundos para exibir a tabela de proximidade RSSI (padrão: 5.0)
        --quiet           : Oculta a listagem linha por linha, mostrando apenas a tabela resumo


7. ROTEIRO DE TESTE E VALIDAÇÃO PASSO A PASSO
---------------------------------------------
1. Inicie o Mosquitto no Windows e confirme que a porta 1883 está aberta.
2. Ligue o Cinto (ESP32-C3). No Serial Monitor a 115200 bps você deverá ver:
   "BLE ADVERTISING INICIADO (NimBLE)" e as linhas periódicas "BLE TX #...".
3. Ligue a Âncora (ESP32). No Serial Monitor você deverá ver:
   - Conexão ao Wi-Fi obtida (com IP da âncora).
   - "Conectando ao MQTT ... OK".
   - Detecção dos pacotes do cinto: "BLE RX [CINTO_OQPNB01 | -XX dBm] ...".
4. Execute `python interface.py --csv leituras.csv`.
   - Você verá em tempo real o fluxo de aceleração, giroscópio, BPM real e o nível
     de sinal RSSI da âncora em relação ao cinto.
